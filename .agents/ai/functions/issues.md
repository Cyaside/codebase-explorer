# Issues Function Guide

## Goal

Explain how support files, issue exports, changelogs, and code signals relate to each other.

## Questions To Answer

- what areas are repeatedly mentioned
- what themes recur across support files
- which paths appear related to recent change pressure
- where does issue history overlap with hotspot analysis

## Evidence To Inspect

Prioritize:
- provided support files
- changelog data
- issue exports
- hotspot candidates
- dependency concentration
- directories or files repeatedly mentioned by name

## Output Shape

The issues output should include:
- frequently mentioned areas
- repeated themes
- source support files used
- a short note about confidence and limitations

## Do Not

- claim issue correlation if no support files were provided
- treat freeform issue text as exact truth about current code
- present stale issue text as current architecture fact

## Done Condition

The issues surface helps a user connect historical noise to actual code areas worth reading.
